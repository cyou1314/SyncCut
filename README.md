# SyncCut — 飞书优先的剪映素材同步助手

SyncCut 将飞书多维表格作为团队音乐、音效、配音和环境音的协作入口，通过 macOS 助手把选中的素材批量导入剪映，或按参数套用到时间轴。

## 产品形态

- **飞书：** 团队成员日常维护项目、素材附件、标签和时间轴参数。
- **SyncCut 云端：** 管理飞书连接、租户隔离、变更事件、同步任务和设备授权。
- **SyncCut Mac：** 获取任务、下载并校验音频、缓存素材、执行剪映本地操作。
- **SyncCut Web 控制台：** 只承担连接配置、设备管理、同步状态和错误诊断，不重复实现飞书文档/素材协作。

## 两种套用方式

1. **批量导入素材库：** 将选中的音乐、音效等素材一次性导入剪映媒体库。
2. **套用到时间轴：** 根据飞书记录中的开始时间、素材入出点、目标音轨、音量和淡入淡出参数，写入剪映工程副本。

时间轴套用必须先复制工程，不覆盖源工程。剪映适配器在未验证版本上拒绝写入。

## 多团队架构

首期先接入一个飞书企业/团队，使用企业自建应用完成真实流程验证。数据模型从第一天起按 tenant 隔离：每个团队拥有独立的飞书连接、多维表格、成员、设备、素材索引和任务。

未来面向其他团队时，按飞书应用商店应用/企业安装授权模式扩展。不同租户的凭证加密存储，Mac 设备和任务均绑定租户。应用商店上架和跨企业授权需另行完成飞书审核与验证，当前不宣称已支持外部租户安装。

## 当前开发状态

本仓库包含产品原型、macOS 助手骨架和飞书优先架构。API 首期正在实现 Bitable 自动化 Webhook 接收、事件去重和飞书 API 适配层。

**尚未完成：** 真实飞书应用授权、完整数据库部署、Bitable 全量/增量同步 Worker、Mac 设备配对、真实剪映导入和时间轴适配。当前代码不能被视为已上线服务。

## 开发结构

- `apps/web/`：SyncCut 控制台原型。
- `apps/api/`：Node.js API、飞书连接器、Webhook 接收和内部任务服务。
- `apps/macos-agent/`：SwiftUI 菜单栏助手。
- `packages/shared/`：跨模块共享的数据契约。
- `apps/api/migrations/`：SyncCut 内部控制面 PostgreSQL 数据结构。
- `docs/`：产品、架构、飞书配置、素材表模板和剪映适配说明。

## 本地运行 API

要求 Node.js 22+ 和 PostgreSQL。

```bash
cd apps/api
cp .env.example .env
# 编辑 .env，填写 DATABASE_URL 等服务端配置
npm install
npm test
npm start
```

执行数据库迁移前，请先创建专用开发数据库，并确认迁移文件内容。不要在生产库中直接试跑。

## 飞书同步机制

- 初始全量同步：通过 Bitable 列表记录 API 分页读取。
- 实时触发：在多维表格工作流/自动化中配置“新增记录/修改记录”触发器，并使用“发送 HTTP 请求”通知 SyncCut。
- 事件处理：Webhook 只传递记录 ID、更新时间等元数据；SyncCut 再通过飞书 API 读取完整记录和附件 token。
- 补偿校验：定时扫描记录更新时间，补偿未送达的通知。
- 附件：读取 Bitable 附件字段的 file_token，通过飞书媒体下载接口获取文件；Mac 端以 SHA-256 校验并按内容哈希缓存。

不要把音频二进制直接塞进自动化 Webhook 请求体。

## Supabase 旧方案说明

`supabase/` 目录保留早期方案作为历史参考。飞书优先架构下不再使用 Supabase Auth 或 Supabase Storage；此前未合并的 Supabase 开发 PR 已被新架构取代。不要将旧目录中的迁移应用到新环境。

## 安全原则

- 飞书 App Secret、用户/租户 Token 仅在服务端使用，凭证加密后存储。
- 浏览器和 Mac 客户端不接收飞书 App Secret。
- 每个团队的连接、事件、素材和设备都必须带 tenant_id 并做授权校验。
- Webhook 使用每条连接独立的 Bearer secret，数据库仅保存其 SHA-256 哈希。
- 设备令牌只保存哈希；支持撤销。
- 不覆盖原始音频、视频和剪映工程。
- 不使用剪映/CapCut CLI，不修改官方应用包，不读取账号 Cookie。
